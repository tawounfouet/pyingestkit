# PyIngestKit 1.0.0rc1 — Full Stability Candidate

Status: **release candidate, not stable**.

PyIngestKit `1.0.0rc1` is the first real V1 package candidate. It consolidates the frozen V1 public API,
compatibility, operational behavior and representative pilot evidence without adding a new ingestion
provider or orchestration capability.

## Candidate contents

- framework package version `1.0.0rc1`;
- maintained demo package version `1.0.0rc1`;
- deterministic plugin discovery and error isolation;
- fail-closed configuration/profile resolution;
- governed CLI commands, exit-code classes and JSON semantics;
- governed logging/redaction behavior;
- V1 public Python API manifest;
- logical persistence and portable schema compatibility contracts;
- five representative pilots covering nine maintained reference jobs;
- PostgreSQL 16 and S3-compatible service-backed E2E qualification;
- clean-wheel installation smoke from built candidate distributions;
- executable V0.6.0 -> 1.0.0rc1 upgrade qualification from the immutable `v0.6.0` tag.

## Upgrade evidence

The RC release-check creates real V0.6 versioned run history, versions and publication state using the
historical `v0.6.0` release, upgrades the same environment to the built `1.0.0rc1` wheels, then proves:

- historical run state is still readable;
- historical DatasetVersion snapshots are still readable;
- PublishedDataset still points at the historical V2 run;
- strict replay succeeds from historical RAW;
- expected and actual fingerprints remain equal to the historical published fingerprint.

## Release governance

This candidate does not move or redefine `v0.6.0`, does not create stable `v1.0.0`, and does not imply
that `1.0.0` is published. After RC1 merge, the exact merge SHA must pass post-merge CI and Security.
Only then may the final stable milestone replace candidate version metadata with `1.0.0`, rerun the full
release-check, create the annotated immutable `v1.0.0` tag and publish final release assets.
