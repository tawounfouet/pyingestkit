# PyIngestKit 2.1.0 Stable Qualification

## Promotion baseline

- Stable target: `2.1.0`
- RC merge baseline: `12a0dbb83933b141cb08909bab3b3d6159293966`
- RC contract fixture: `tests/contract/fixtures/governance_v2_1_rc1.json`
- Stable contract fixture: `tests/contract/fixtures/governance_v2_1_stable.json`
- Stable branch: `release/v2.1.0`

LOT-30 is promotion-only. Any governance capability, signature, event semantic
or provider guarantee change requires returning to a pre-stable candidate.

## Stable freeze

The LOT-30 machine contract freezes:

- exact 11-symbol PyIngestKit 2.0 root;
- exact LOT-23 governance namespace exports;
- exact `PublicationLedger`, `ConditionalDatasetPublisher` and
  `DatasetVersionGarbageCollector` method signatures;
- `RetentionPolicy(keep_last=1, min_age_seconds=None)`;

- exact lifecycle event enum values;
- framework-owned publication revision serialization;
- exact governance provider inventory;
- conditional-publication result statuses;
- GC deletion and reconciliation statuses;
- rollback result contract.

## Post-merge publication gate

After merge, the exact stable merge SHA must pass:

```text
CI       PASS
Security PASS
Docs     PASS
```

Only that exact post-merge SHA is eligible for the `v2.1.0` tag and stable
GitHub release.

## Compatibility rule

The original 2.0 compatibility fixture remains separately enforced. Stable
2.1 governance is additive and does not reinterpret 2.0 applications or wire
contracts.
