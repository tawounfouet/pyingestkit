# PyIngestKit 2.1.0

## Status

**Stable — LOT-30.**

PyIngestKit 2.1.0 promotes the fully qualified `2.1.0rc1` governance contract
without adding or changing governance semantics. The exact PyIngestKit 2.0
package root, runtime signature, provider Protocols and version-1 portable wire
contracts remain the compatibility baseline for the maintained 2.x line.

## What 2.1 adds

PyIngestKit 2.1 adds opt-in publication and dataset-lifecycle governance through
qualified namespaces rather than widening the package root.

The stable governance surface includes:

- durable publication intents and append-only lifecycle evidence;
- in-memory and PostgreSQL lifecycle ledgers;
- filesystem compare-and-swap publication with process locking and ABA-safe
  framework revisions;
- endpoint-qualified S3 conditional publication using provider-enforced
  preconditions;
- deterministic retention planning and durable version holds;
- guarded filesystem and S3 garbage collection with stale-plan protection;
- governed rollback as a new CAS publication to an existing immutable
  DatasetVersion;
- explicit UNKNOWN_OUTCOME reconciliation from observable provider truth;
- mixed-provider crash/restart recovery evidence.

## Stable package root

The package root remains exactly the 2.0 root:

```python
from pyingestkit import (
    ArtifactReference,
    DatasetVersion,
    DatasetVersionReference,
    IngestionDefinition,
    IngestionResult,
    IngestionRun,
    IngestionRunId,
    IngestionRuntime,
    PublishedDataset,
    ResourceReference,
    Source,
)
```

Applications that do not use governance APIs do not need to change imports or
runtime composition.

## Qualified governance namespaces

Governance remains additive under:

```text
pyingestkit.governance
pyingestkit.governance.retention
pyingestkit.governance.rollback
```

The stable provider implementations are:

```text
FileConditionalDatasetPublisher
S3ConditionalDatasetPublisher
MemoryPublicationLedger
PostgresPublicationLedger
FileDatasetVersionGarbageCollector
S3DatasetVersionGarbageCollector
```

## Stable lifecycle guarantees

- conditional publication is compare-and-swap, not blind overwrite;
- exactly one writer succeeds for the same expected revision;
- framework-owned publication revisions prevent ABA;
- provider ETags/tokens do not leak into portable revision contracts;
- UNKNOWN_OUTCOME never causes blind retry;
- reconciliation inspects provider truth;
- publication operation identity is durable and idempotent;
- PostgreSQL lifecycle evidence survives restart;
- secrets are rejected before ledger persistence;
- current, held, unresolved and integrity-unverified versions are protected
  from garbage collection;
- stale garbage-collection plans fail closed;
- rollback never mutates historical DatasetVersion bytes.

## Lifecycle persistence schema

The durable publication-intent and lifecycle-event codec is frozen at
`schema_version = 1` for PyIngestKit 2.1.0.

The stable PostgreSQL tables remain:

```text
pyingestkit_v2_publication_operation
pyingestkit_v2_publication_event
pyingestkit_v2_version_hold
```

This lifecycle schema is separate from the already-frozen 2.0 portable boundary
contract versions.

## Provider qualification

See `docs/reference/provider-compatibility-v2.md` for the 2.x support matrix.

2.1 stable qualification covers:

- File + Memory;
- File + PostgreSQL;
- S3 + Memory;
- S3 + PostgreSQL;
- filesystem/S3 guarded GC;
- filesystem/S3 governed rollback;
- PostgreSQL restart recovery;
- clean base wheel/sdist and provider extras.
