# Review: V0.6.0 Configuration Auto-Discovery & Fail-Fast Backend Validation

## Overview

Ce document retrace la conception, l'implémentation et la validation de deux améliorations architecturales majeures apportées au runtime de **PyIngestKit V0.6.0** :
1. **La résolution dynamique et l'auto-découverte de configuration** (CLI `--config`, variable `PYINGEST_CONFIG`, détection des fichiers par défaut).
2. **Le système de contrats de backends requis et de validation Fail-Fast** (`requires_artifacts`, `requires_metadata`).

---

## Problématiques & Contexte

### 1. Friction d'exécution manuelle (`--config`)
Auparavant, le CLI PyIngestKit exigeait systématiquement le passage d'un argument explicite `--config <chemin.yml>` pour tout job dépendant d'un backend autre que les valeurs locales par défaut. En l'absence de ce paramètre, le runtime basculait silencieusement sur un backend local en mémoire ou échouait tardivement en plein milieu de l'exécution d'un step.

### 2. Échecs tardifs et corruptions d'intégrité (Late-Failure & FK Constraints)
Lorsqu'un job déclarant ou utilisant un backend spécifique (ex: un step publiant vers un `S3ArtifactStore` ou un `PostgresMetadataStore`) était lancé avec une configuration incompatible :
- Le runtime initialisait l'en-tête de run dans SQLite (`.pyingest/state/pyingest.sqlite3`).
- Un step ultérieur tentait d'enregistrer des publications ou des `target_loads` directement dans PostgreSQL.
- **Résultat** : Une exception `IntegrityError` (violation de clé étrangère sur `run_id`) survenait après plusieurs secondes d'exécution, laissant le système dans un état inconsistant.

## Solutions Architecturales Implémentées

### 1. Hiérarchie de résolution de configuration ([loader.py](file:///Users/awf/workspace/professionnal/webtech/clients/prepavogt-alumni/packages/pyingestkit-v0.6.0/src/pyingestkit/config/loader.py))

La fonction `load_config(path: Path | None = None)` applique désormais une résolution ordonnée et déterministe :
1. **Flag explicite CLI** : `--config <fichier.yml>` ou `-c`.
2. **Variable d'environnement** : `PYINGEST_CONFIG=<chemin.yml>`.
3. **Auto-découverte locale** : Recherche successive de `pyingest.yml`, `pyingestkit.yml`, et `.pyingest.yml` dans le répertoire courant.
4. **Valeurs par défaut** : Stockage local (filesystem) et métadonnées SQLite.

```python
DEFAULT_CONFIG_FILES: tuple[str, ...] = (
    "pyingest.yml",
    "pyingestkit.yml",
    ".pyingest.yml",
)

def resolve_config_path(path: Path | None = None) -> Path | None:
    if path is not None:
        return path

    env_path = os.getenv("PYINGEST_CONFIG")
    if env_path and env_path.strip():
        candidate = Path(env_path.strip())
        if candidate.exists():
            return candidate
        raise ConfigurationError(
            f"Configuration file specified in PYINGEST_CONFIG={env_path!r} does not exist"
        )

    for filename in DEFAULT_CONFIG_FILES:
        candidate = Path(filename)
        if candidate.exists():
            return candidate

    return None
```

### 3. Interception Fail-Fast pré-exécution ([common.py](file:///Users/awf/workspace/professionnal/webtech/clients/prepavogt-alumni/packages/pyingestkit-v0.6.0/src/pyingestkit/cli/common.py))

Avant d'instancier le `Runner` ou d'exécuter le moindre step réseau/fichier, le CLI valide la compatibilité :

```python
def validate_job_requirements_or_exit(job: Job, project_config: PyIngestKitConfig | None) -> None:
    if project_config is None:
        return

    if job.requires_artifacts:
        actual_artifacts = str(project_config.artifacts.backend).lower()
        required_artifacts = job.requires_artifacts.lower()
        if actual_artifacts != required_artifacts:
            emit_error_and_exit(
                f"Ingestion job '{job.id}' requires an artifact backend of type "
                f"'{required_artifacts}', but '{actual_artifacts}' is configured.\n"
                f"Please specify a compatible configuration file using `--config <file.yml>` "
                f"or set the PYINGEST_CONFIG environment variable."
            )

    if job.requires_metadata:
        actual_metadata = str(project_config.metadata.backend).lower()
        required_metadata = job.requires_metadata.lower()
        if actual_metadata != required_metadata:
            emit_error_and_exit(
                f"Ingestion job '{job.id}' requires a metadata backend of type "
                f"'{required_metadata}', but '{actual_metadata}' is configured.\n"
                f"Please specify a compatible configuration file using `--config <file.yml>` "
                f"or set the PYINGEST_CONFIG environment variable."
            )
```
