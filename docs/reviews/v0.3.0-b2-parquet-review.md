# PyIngestKit V0.3.0-rc1 — Parquet Implementation Review

## Scope

V0.3.0-rc1 builds directly on V0.3.0-b1 and adds `ParquetParser` through the optional `parquet`
extra backed by PyArrow.

## Boundary

The parser is an adapter, not a dataframe abstraction. PyArrow is loaded lazily and the resulting
records are materialized into the existing neutral `Dataset`. Pandas and Polars remain absent from
the core contract.

## Memory guardrail

V0.3 Parquet parsing is explicitly in-memory. `max_rows` uses Parquet metadata before table
materialization to reject unexpectedly large payloads. `columns` allows structural projection.
Streaming/batched datasets remain future architecture work rather than being hidden behind the V0.3
API.

## Local qualification in the artifact build environment

The PyArrow-independent parser contract is validated with a deterministic backend double, including
lazy optional-dependency handling, projection and the pre-materialization row guard. PyArrow is not
installed in this assembly environment, so a real-PyArrow extras smoke test and the complete
`make verify` gate must be executed in the project development/CI environment before promotion.
