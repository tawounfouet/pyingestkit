# PyIngestKit V0.6.0 — Live Configuration Inspection & Origin Tracing Review

## 1. Executive Summary

As PyIngestKit evolved to support multi-environment configurations (`dev`, `stg`, `prod`), cloud object storage (S3, Cloudflare R2, MinIO), and multiple metadata backends (SQLite, PostgreSQL), determining the exact configuration loaded at runtime became a critical developer-experience and operational requirement.

To eliminate ambiguity, prevent accidental cross-environment operations, and enable automated CI/CD inspection, PyIngestKit V0.6.0 introduces the **`pyingest config`** command.

---

## 2. Problem Statement & Motivation

Prior to this feature:
1. **Ambiguous Runtime State**: When running `pyingest run <job_id>` with environment variables (`PYINGEST_ENV`, `PYINGEST_CONFIG`) or working-directory YAML files, developers had no built-in way to verify which configuration file was actually selected.
2. **Operational Risk**: In enterprise setups, running a job against production PostgreSQL instead of local SQLite could happen if an environment variable was accidentally inherited.
3. **Hidden Endpoint Details**: S3 endpoint overrides, bucket prefixes, and target table mappings required manual file inspection or source code checks.
4. **Credential Exposure Risk**: Dumping raw configs or environment files could leak sensitive database passwords or cloud access keys into terminal history or CI logs.

## 3. Architecture & Implementation

### 3.1. Origin-Aware Configuration Resolution

The configuration loader was enhanced with [`resolve_config_path_with_source()`](file:///Users/awf/workspace/professionnal/webtech/clients/prepavogt-alumni/packages/pyingestkit-v0.6.0/src/pyingestkit/config/loader.py):

```python
def resolve_config_path_with_source(path: Path | None = None) -> tuple[Path | None, str]:
    """Resolve the configuration file path and return the resolution origin method."""
    if path is not None:
        return path, "explicit (--config)"

    env_path = os.getenv("PYINGEST_CONFIG")
    if env_path and env_path.strip():
        candidate = Path(env_path.strip())
        if candidate.exists():
            return candidate, f"environment (PYINGEST_CONFIG={env_path.strip()})"
        raise ConfigurationError(...)

    env_name = os.getenv("PYINGEST_ENV")
    if env_name and env_name.strip():
        candidate = Path(f"pyingest.yml.{env_name.strip()}")
        if candidate.exists():
            return candidate, f"profile (PYINGEST_ENV={env_name.strip()} -> {candidate})"

    for filename in DEFAULT_CONFIG_FILES:
        candidate = Path(filename)
        if candidate.exists():
            return candidate, f"default_file ({filename})"

    return None, "fallback (default in-memory)"
```

This returns not only the resolved file path, but the exact mechanism through which it was discovered.

### 3.2. Automated Credential & Secret Masking

Security is enforced by default. Database connection strings containing user credentials (`postgresql://user:password@host:port/db`) are parsed and masked:

```python
def _mask_url(url: str | None) -> str | None:
    if not url:
        return url
    try:
        parsed = urlparse(url)
        if parsed.password:
            user = parsed.username or ""
            host = parsed.hostname or ""
            port = f":{parsed.port}" if parsed.port else ""
            netloc = f"{user}:******@{host}{port}"
            return urlunparse(parsed._replace(netloc=netloc))
        return url
    except Exception:
        return re.sub(r":([^/@]+)@", r":******@", url)
```

If an operator explicitly needs to debug credentials, the `--show-secrets` flag can be provided.

### 3.3. Command Implementation

The command is implemented in [`src/pyingestkit/cli/commands/config.py`](file:///Users/awf/workspace/professionnal/webtech/clients/prepavogt-alumni/packages/pyingestkit-v0.6.0/src/pyingestkit/cli/commands/config.py) and registered as `pyingest config`.

Supported options:
- `--config` / `-c`: Inspect an arbitrary configuration file.
- `--workspace` / `-w`: Override the runtime workspace path.
- `--show-secrets`: Reveal plain-text passwords and credentials.
- `--json`: Output a structured, machine-readable JSON document.
