    V0.4.0 stable format freeze

    V0.4.0 freezes the ADR-034 canonical Dataset fingerprint codec at version 1 and the ADR-036 Dataset snapshot format at snapshot_version = "1". Portable diff reports are frozen at report_version = "1" as documented by the V0.4 release validation guide.

    V0.5 PostgreSQL persistence targets

    • ADR-041 — Target abstraction exposes one atomic load operation
    • ADR-042 — PostgresTarget uses SQLAlchemy Core with psycopg and no ORM
    • ADR-043 — PostgreSQL Dataset type mapping is deterministic and conservative
    • ADR-044 — psycopg 3 COPY is the PostgreSQL production bulk-load path
    • ADR-045 — Target-load metadata is an additive run-linked capability
    • ADR-046 — PostgreSQL content load modes share one atomic transaction boundary
    • ADR-047 — Target-load idempotency is history-driven and remains outside Target

    V0.6 Object Storage

    • ADR-048 — Artifact URI and local materialization are separate identities
    • ADR-049 — ArtifactStore URI support is additive
    • ADR-050 — S3ArtifactStore owns remote RAW and local cache
    • ADR-051 — S3 RAW is immutable and integrity-checked
    • ADR-052 — StoredArtifact is an additive durable run-artifact reference
    • ADR-053 — S3 JSON run artifacts follow run-scoped lifecycle semantics
    • ADR-054 — S3 DatasetVersion storage is immutable; publication is one mutable pointer

    V1 Stable Framework Contract

    • ADR-055 — V1 public API and product scope are governed by an explicit manifest
    • ADR-056 — V1 compatibility is enforced at logical contracts and versioned persistence boundaries
    • ADR-057 — V1 operational surfaces are frozen by explicit behavioral contracts
    • ADR-058 — V1 readiness is demonstrated by representative pilots and executable documentation contracts
    • ADR-059 — V1 RC1 is a real package candidate and must upgrade the immutable V0.6 baseline
